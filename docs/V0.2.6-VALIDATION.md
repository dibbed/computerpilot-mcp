# v0.2.6 Runtime Reliability & Observability Validation

Validation date: 2026-09-24  
Validated implementation commit: a5b10dfac2a47ca24af50e98f009ce1da9ae7a4b  
Release: 0.2.6  
Tool surface: 110 unique MCP tools

This document records the release evidence for v0.2.6. Validation was executed from a detached Git worktree so pytest, benchmark, soak, startup checks, and temporary state could not mutate the active MCP runtime state.

The final release tag is expected to contain only release evidence/documentation changes after the validated implementation commit. No production-code change should be introduced after this baseline without repeating the relevant gates.

## Release scope

v0.2.6 hardens the correctness work shipped in v0.2.5 and improves local runtime observability and long-running job UX.

| Area | Result | Evidence |
| --- | --- | --- |
| Durable job contract | PASS | Workflow durable-job submission, wait, cancellation, persisted external refs, result storage, deduplication, and request-key reconciliation consistently use the public `job_id` contract. |
| Durable job progress | PASS | `job_wait` returns existing output immediately, otherwise emits a bounded default five-second heartbeat with incremental stdout/stderr chunks and resumable byte cursors while preserving explicit short-timeout behavior. |
| Reconciliation semantics | PASS | HTTP expected 4xx/5xx statuses are observable, redirects are checked without implicit following, oversized bodies cannot falsely prove hashes, and staged Git paths are parsed NUL-delimited so Unicode filenames remain literal. |
| Workflow retry/cancellation | PASS | Cancellation received during retry backoff prevents another attempt, and workflow leases remain renewed through retry backoff. |
| Workflow idempotency | PASS | New workflow idempotency identity includes exact workflow inputs; migrated legacy rows remain compatible when exact historical inputs were unavailable. |
| LSP edit safety | PASS | Workspace edits are canonicalized and merged per file, malformed/reversed/overlapping edits are rejected, UTF-16 positions cover CRLF/surrogates/edge lines, and symbol rename requires per-file SHA-256 preconditions. |
| Recovery journal correctness | PASS | Concurrent append/compaction is serialized, operator acknowledgement evidence remains stable through compaction, workflow IDs are included in generic recovery targets, and unresolved standalone recovery state degrades health. |
| Windows interprocess locking | PASS | Audit and project-memory first-open lock races are removed by locking zero-length lock files directly. |
| Local control panel | PASS | The loopback panel exposes richer lifecycle/process/job/storage/event/error data and is enforced as an English-only LTR interface. |
| Windows test determinism | PASS | Durable-job restart tests use explicit start/release handshakes, watchdog readiness is explicit, lease-heartbeat/backoff tests use accelerated deterministic timing without weakening production TTL/backoff bounds, and new regression tests satisfy the repository-wide mypy gate. |

## Packaging convention

v0.2.6 uses the same deterministic release-archive convention as v0.2.5:

    git archive --format=zip --prefix=windows-agent-mcp-v0.2.6/ --output=windows-agent-mcp-v0.2.6-windows-amd64.zip v0.2.6

The convention was independently verified against the published v0.2.5 GitHub asset: reproducing v0.2.5 with the equivalent prefix produced the exact published size and SHA-256.

The v0.2.6 archive SHA-256 and independent extracted-package validation are published in the GitHub Release because the final archive is computed from the final release tag.

## Release boundaries

This release does not change the bundled upstream tunnel-client binary version. Project version `0.2.6` remains independent from the bundled tunnel-client executable provenance documented in `BINARY_PROVENANCE.md`.

The release also does not add arbitrary shell workflow actions, automatic replay of uncertain side effects, generic deployment adapters, or browser/desktop workflow adapters without concrete runtime contracts.
