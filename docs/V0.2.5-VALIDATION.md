## Crash-window gates

The release suite covers each required crash point:

1. After operation RUNNING checkpoint, before side effect: expired lease / restart converts a non-terminal current operation to uncertain.
2. After side effect, before result persistence: lost-result tests cover Git stage, Git commit, durable-job submission, and multi-file patch publication; reconciliation succeeds without replay when evidence is conclusive.
3. After result persistence, before step checkpoint: restart repairs the step/workflow aggregate from the already-persisted terminal operation.
4. After step checkpoint, before workflow advance: restart advances the aggregate from persisted succeeded operation/step truth without replay.
5. During lease renewal: heartbeat loss/fencing tests prove stale ownership cannot publish the final checkpoint.
6. During cancellation: cancellation racing with a running action preserves a completed effect and stops remaining steps; restart from cancelling preserves terminal operation truth before cancelling the aggregate.
7. During reconciliation: automated reconciliation racing manual acknowledgement is serialized by operation version/CAS; exactly one resolver wins.

## Concurrency gates

- Two executors racing the same queued workflow execute the action exactly once.
- Lease takeover after expiry rejects stale checkpoint/release tokens.
- Cancellation requested while an action is running preserves the operation result if the action completes.
- Reconcile and manual acknowledgement racing the same version have one winner and one version conflict.
- Retention running concurrently with repeated status reads does not remove or corrupt the active workflow.
- Oldest-first queue selection finds queued workflows outside a greater-than-100-record recent-history window.

## Windows test-state isolation

The previous fixed .agent_state/pytest-tmp collided with live MCP runtime state. Removing basetemp entirely exposed a separate host pytest-current permission failure. The final configuration uses ignored repository-local .pytest-tmp, outside .agent_state.

Evidence:
- two consecutive focused pytest executions passed using the new default basetemp;
- final 554-test full suite passed;
- the live MCP state directory was not used as pytest basetemp;
- no WinError 5 occurred in the final validation worktree.

## Release-state boundaries

The release intentionally does not add arbitrary shell workflow actions, automatic replay of uncertain side effects, general DAG/parallel workflow execution, a generic secret vault, persistent PowerShell/REPL, persistent LSP pools, general deployment adapters, or browser/desktop workflow adapters without concrete runtime contracts. Those remain post-v0.2.5 work.
