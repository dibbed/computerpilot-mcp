# ComputerPilot MCP v0.7.0 Validation

Validation date: 2026-10-07

This document records feature-branch validation for the v0.7 Adaptive Execution Router before release preparation. The implementation baseline before the documentation/validation commit is `1a355e36dbea4bb0dc309cb002f541da18f14290` (`feat(panel): add execution routing observability`). Runtime/package metadata intentionally remains `0.6.0` until the separate v0.7.0 release-preparation flow.

## Scope

The v0.7 feature branch adds a deterministic and explainable execution decision layer without adding a universal dispatcher. The validated scope includes:

- shared execution intent/route/tool metadata;
- deterministic `deterministic-v1` candidate generation and recommendation;
- profile/platform capability filtering from the live registered MCP catalog;
- hard safety constraints before ranking;
- read-only `execution_candidates` and `execution_recommend` MCP tools;
- `recommend_tools` execution metadata enrichment without changing its keyword ordering contract;
- workflow schema v6 route metadata and legacy migration compatibility;
- route persistence before routed workflow side effects;
- route mismatch fail-closed behavior and bounded fallback history;
- no router replay for uncertain workflow effects;
- bounded in-memory routing metrics in `server_health`;
- English-only Execution Routing observability in the loopback Control Panel.

There is intentionally no `execution_run` tool in v0.7. `visual.desktop` remains reserved and unavailable.

## Safety / Compatibility Evidence

- Candidate generation uses only supplied registered tool names plus supplied platform capabilities; shared catalog metadata cannot create availability.
- `deterministic-v1` applies hard safety constraints before ranking.
- Raw desktop requires explicit permission and cannot be selected for destructive requests.
- Destructive ambiguous semantic targets fail closed.
- Stale semantic references do not fall back to raw coordinates.
- Macro-preservation requirements reject routes that cannot prove the required fidelity.
- `visual.desktop` is unavailable in this phase.
- Existing workflows without `execution_intent` retain the prior executor path.
- Routed workflow decisions are persisted before action side effects and must match the fixed allowlisted workflow action route.
- Uncertain workflow effects remain reconciliation-only; the router is not invoked to blindly reroute/replay them.
- Router metrics are bounded and retain route/intent metadata only, not raw prompts, document bodies, screenshots, credentials, or secrets.

## Hosted Validation

Hosted CI evidence is intentionally not claimed in this local record yet. Before merge, the feature PR must reach terminal success for the repository-required CI matrix, Platform Release Validation, and Release Packaging Smoke. The branch must not be merged while any required hosted gate is red.

- v0.7 recommends routes but intentionally does not expose a universal execution dispatcher.
- Visual grounding is deferred to the later visual-desktop phase.
