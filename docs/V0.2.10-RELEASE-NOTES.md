# v0.2.10 - Live Tunnel Runtime Migration Fix

v0.2.10 is a focused patch release for the managed Secure Tunnel bootstrap introduced in v0.2.9.

## Fixed

On Windows, an upgrade from an older managed full-client cache could fail when the old `tunnel-client.exe` was still running from the same upstream version directory. The v0.2.9 installer attempted to replace the whole `<version>/<platform>` directory, and Windows correctly rejected deletion of the live executable with an access-denied error.

v0.2.10 installs `tunnel-client-runtime-cloudflared` in a dedicated flavor-specific directory:

`.agent_state/tunnel-runtime/<version>/<platform>/tunnel-client-runtime-cloudflared/`

This allows the verified new runtime to be downloaded and published while the legacy full-client process keeps running. The next cold start can then select the new managed flavor without requiring the live legacy executable to be deleted first.

## Validation

- Focused tunnel/Doctor/package tests passed.
- Full pytest passed.
- Ruff and mypy passed.
- A real Windows migration was executed while the legacy `tunnel-client.exe` remained live.
- The new managed runtime was installed successfully beside the legacy runtime.
- `current.json` was updated to the verified `tunnel-client-runtime-cloudflared.exe` path.
- The legacy process continued running during migration.

No upstream tunnel or Cloudflared binaries are bundled in project release artifacts.
