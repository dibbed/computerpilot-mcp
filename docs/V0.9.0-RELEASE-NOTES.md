# ComputerPilot MCP v0.9.0 — Coding Intelligence and Bounded Parallel Execution

Version 0.9.0 collects the changes since the immutable `v0.8.0` tag. It adds durable background verification, opt-in parallel workflows, persistent language intelligence, multilingual verification and bounded native file batching. The existing external-extension foundation remains available without becoming a native dependency.

## What changed since 0.8.0

### Durable verification and parallel workflows

- `start_verification` submits change-aware verification as a durable job. Use `job_wait`, `job_status` and `job_output` to collect progress and the final result after reconnecting. Requests pin source/base identity; stale inputs cannot become fresh success.
- Opt-in DAG workflows persist dependencies, attempts, resource ownership and shared capacity. Independent branches can overlap; sequential definitions keep their existing behavior. `MCP_WORKFLOW_DAG_ENABLED` remains off by default.
- Shared durable path/host claims coordinate native edits, document publication, semantic edits, managed Git, jobs and analyzers. Queue policy fingerprints prevent incompatible budget settings from admitting work across processes. Unresolved ownership remains fenced after crashes or incomplete cleanup.
- Job dispatch records its pre-spawn phase durably. Restart recovery distinguishes proven non-dispatch from possible effects and never blindly replays uncertain work. Cancellation retains ownership until actual process cleanup finishes.
- Windows Job Object accounting and captured process handles, plus POSIX descendant cleanup, strengthen process-tree termination. Workflow workers explicitly select advisory routing or native-only routing.

### Language and project intelligence

- The seven read-only LSP tools accept typed requests while preserving supported legacy request shapes. Fixed method validation rejects arbitrary protocol dispatch.
- Persistent LSP sessions are opt-in through `MCP_LSP_PERSISTENT_ENABLED` and reviewed `MCP_LSP_PROVIDERS_CONFIG`. A bounded owner handles queues, documents, snapshots, invalidation, timeouts, restarts and cleanup quarantine.
- Python, TypeScript and PHP providers have recorded Windows real-provider acceptance for definition, references and clean/error/repaired diagnostics. TypeScript/PHP push diagnostics are supported; PHP cold indexing can require document priming. Free Intelephense acceptance does not include premium rename/code-action features. Providers are never installed or activated implicitly.
- Opt-in multilingual `code_context` adds provider-qualified relations and a bounded single-flight cache. Omitted language selection retains the Python AST path. Project evidence uses bounded manifest reads and consumption-time identity/hash validation.
- Workspace edits require source hashes, UTF-16 positions and matching version evidence. Durable preimage backups and mutation checkpoints precede writes; rollback restores only this operation's unchanged postimages. Unknown outcomes retain evidence without replay.

### Multilingual testing

- `affected_tests`, `verify_changes`, durable verification and workflow verification preserve Python defaults. `test_backend="auto"` adds bounded package-runner discovery and conservative package-suite planning.
- Discovery does not execute package scripts or JavaScript/XML configuration. Direct runner helpers validate installed runtime, entrypoint and workspace identity with fixed argv for supported Jest 29, Vitest 3, PHPUnit 11 and Pest 3 runners.
- Unsupported, missing, stale, zero-test or incomplete results remain unknown; they never become successful coverage. External runner code executes with the account's permissions and is not an OS sandbox.

### Native file batching and compact catalogs

- `native_read_batch` reads 1–16 independent local text windows with ordered, independent outcomes. Select the seven-tool `read_batch` profile or add it to `full` with `MCP_NATIVE_READ_BATCH_ENABLED=1`.
- Windows `full` contains 151 native tools by default, versus 150 in 0.8.0; opting into Batch adds one, giving 152. The opt-in `coding_core` profile exposes 43 tools. All eleven named profiles retain platform filtering and pre-dispatch eligibility checks.
- Batch caps concurrency at four active batches and four actual reads per server, 2 MiB per source file, 8 MiB total sources, 64 KiB requested text and 192 KiB SDK response. Cancellation does not claim synchronous I/O was physically stopped, and the result is not an atomic multi-file snapshot.
- Windows reads reuse immutable ctypes API declarations while preserving per-read handles, ancestor/reparse checks and source checks. Shared claim connections retain FULL SQLite durability and generation-safe cleanup.
- The recorded 2026-10-28 local 30-pair nearest-rank single-file overhead passed the unchanged 5 ms gate: memory 4.5592 ms, stdio 4.6566 ms and loopback HTTP 4.6430 ms. A contended failed run is retained in the evidence.
- The connected GPT plugin/Tunnel benchmark completed 1,470 calls without errors: N16 p95 fell from 9.895 s for the fastest direct mode to 1.646 s for Batch (83.37%); N4 fell from 4.587 s to 1.680 s. These are historical measured connection results, not a guarantee for every host/load. See [the measured acceptance](development/NATIVE-READ-BATCH-LIVE-ACCEPTANCE-2026-10-28.md). Use `read_file` for one file.
- Typed output contracts for ten existing tools and compact native output schemas preserve wire envelopes, nullability, uncertainty and runtime validation. Catalog bytes/token estimates do not prove model prompt cost or model quality.

### Operations, safety and observability

- Native mutation audit/timing, recovery references and durable job workers use bounded private correlation metadata. Phase tracing separates admission, execution and serialization; measured native time is not network or model inference latency.
- Startup/Doctor/health use bounded deadlines, owned cleanup and disposable state. A health probe no longer opens operator job/workflow stores or executes their queued work.
- Windows startup can load persistent local `runtime-settings.cmd`; the guarded Batch activation script preflights idle state and preserves settings for recovery through the existing supervisor. Client catalogs still require refresh/reconnection after registration changes.
- Backup retention adds a file-count quota while protecting unresolved recovery restore points. Project/test discovery excludes generated worktrees, fixtures and dependency directories without hiding explicitly selected paths.
- Direct UIA mutations now preserve pre-dispatch evidence and uncertainty. Git read/discovery commands suppress hooks such as external diff/textconv, fsmonitor and implicit network work; explicit terminal commands keep their existing semantics.
- Extension cancellation, lifecycle publication, telemetry isolation and fixture synchronization received regression fixes. Zero-extension operation and the protocol name `ali_windows_agent_mcp` remain compatible.

The dated [changelog](../CHANGELOG.md#090---2026-10-29) retains the complete implementation history. [Validation](V0.9.0-VALIDATION.md) distinguishes current release checks from the earlier provider and performance measurements.

## Upgrade and rollback

1. Drain active mutations, jobs and workflows before replacing a running installation. Preserve `.secrets`, `.agent_state`, `memory`, provider configuration and local runtime settings. Do not overlay private state from a release archive.
2. Take consistent SQLite backups using the SQLite connection backup API while preserving recovery journals and pinned backups. Do not copy an actively written database without its proper backup procedure.
3. Upgrade all processes sharing state together. Workflow schema moves from 6 in 0.8.0 to 11; job schema moves from 3 to 4. Migrations preserve history and fence unknown ownership. The newer schema is not backward compatible with an older binary.
4. Verify startup, isolated health and Full Doctor before enabling optional features; refresh/reconnect MCP clients after restart. `full` stays the package default. Batch, persistent LSP, DAG execution and external providers remain explicit operator choices. Existing installation overrides are preserved.
5. To roll back, drain and restore the matching pre-upgrade binaries **and** consistent state backups. Do not point 0.8.0 at an upgraded workflow/jobs database, delete claims, or discard unresolved evidence. Disabling a feature is not database rollback.

## Scope and known limits

Visual grounding, delegated/nested browser autonomy, mixed Git/search Batch, interactive shell/REPL sessions, arbitrary `execution_run`, external workflow actions and live profile switching are not added. The `coding_core` real-model UX comparison remains unverified. Real LSP provider evidence is Windows-specific; Linux/macOS core CI is a separate claim. Linux arm64 and macOS amd64 archives are package targets without dedicated native hosted execution.

## Release assets

The guarded publication workflow builds five deterministic archives from the exact validated release SHA: Windows amd64 ZIP; Linux amd64/arm64 and macOS amd64/arm64 tar.gz, plus `SHA256SUMS.txt`. Each archive includes `RELEASE-MANIFEST.json` with source commit/version/target and excludes local runtime state and credentials. Upstream tunnel binaries are downloaded and verified separately; this release does not change the operator's Tunnel endpoint or runtime settings.
