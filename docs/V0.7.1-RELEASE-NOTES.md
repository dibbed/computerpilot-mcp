# ComputerPilot MCP v0.7.1 - Windows Console Shutdown Reliability

ComputerPilot MCP v0.7.1 is a focused patch release for Windows console shutdown behavior after the v0.7.0 Adaptive Execution Router release.

The patch does not add or remove MCP tools, change workflow schemas, alter execution-router policy, or change the cross-platform capability contract. It fixes the Windows launcher/supervisor interrupt path so intentional console shutdown is graceful on the first Ctrl+C and promptly forceable on the second.

## Highlights

### Graceful first Ctrl+C

- Run the live ComputerPilot bootstrap through the virtual-environment Python process rather than keeping PowerShell in the live process chain after environment creation.
- Let the Supervisor receive Windows console interrupts directly.
- Treat the first Ctrl+C as an intentional graceful stop request.
- Preserve lifecycle drain/stop coordination instead of immediately killing the runtime.
- Prevent an intentional exit code `130` / Windows Ctrl+C termination from entering the launcher crash-restart loop.

### Prompt forced shutdown on the second Ctrl+C

- Track console interrupt count inside the Supervisor.
- Let a second Ctrl+C set an explicit force-stop signal.
- Abort a long runtime drain/stop wait when force-stop is requested.
- Shorten process cleanup waits during a forced shutdown so the operator can exit promptly.
- Record whether shutdown cleanup was forced in the drain result.

### Signal-path safety

- Use a re-entrant Supervisor lock for the console-shutdown path so a signal arriving while the main thread is already inside lock-protected lifecycle code cannot deadlock itself.
- Install the SIGINT handler only from the main thread and restore the previous handler during Supervisor teardown.
- Keep `scripts.bootstrap` and `scripts.supervisor` in one Python process for the live start path so console control signals are not obscured by an intermediate PowerShell process.

## Compatibility

- Public package/project identity remains `computerpilot-mcp` / ComputerPilot MCP.
- Protocol-level MCP server identifier remains `ali_windows_agent_mcp`.
- Windows full-profile catalog remains 150 unique tools.
- `deterministic-v1` routing behavior from v0.7.0 is unchanged.
- Workflow schema remains v6.
- Semantic Browser, Native Documents, durable jobs, recovery, workflows, and existing tool profiles are unchanged.
- Linux/macOS portable-core behavior is unchanged; this patch targets the Windows console launcher and Supervisor interrupt path.

## Known limits

- The first Ctrl+C requests graceful shutdown, so a mutation-aware drain may still take bounded time when work is active. Pressing Ctrl+C again requests the force-stop path.
- This patch does not introduce new visual-grounding, external-MCP extension, or delegated-browser capabilities. Those remain future roadmap work.
