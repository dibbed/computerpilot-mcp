# Tunnel MCP Architecture Expansion Plan

## Scope

این سند برنامه معماری بعد از v0.2.0 پروژه Tunnel MCP است.
هدف این فازها اضافه کردن قدرت خام بیشتر نیست، بلکه تبدیل MCP فعلی به یک platform قابل اعتماد برای automation، development workflow و عملیات چندمرحله‌ای است.

اصل اصلی:

> اول primitiveهای reliability و semantic control ساخته می‌شوند، سپس orchestration روی آن‌ها ساخته می‌شود.

---

# Current State

پروژه اکنون دارای قابلیت‌هایی مانند:

- developer intelligence
- semantic code operations
- transactional patching
- diagnostics
- validation workflows
- durable jobs
- browser automation
- desktop automation اولیه
- recovery journal

است.

اما چند فاصله معماری باقی مانده:

1. عملیات side-effect دار هنوز همیشه قابل reconciliation نیستند.
2. desktop automation بیشتر coordinate-based است.
3. تعداد زیاد toolها نیازمند discovery بهتر است.
4. workflow چندمرحله‌ای durable هنوز primitive عمومی ندارد.

---

# Architecture Principle

چهار بخش مستقل ساخته می‌شوند:

```
Recovery/Reconciliation
        ↓
Windows UI Automation
        ↓
Tool Catalog Profiles
        ↓
Durable Workflow Orchestration
```

Workflow engine نباید قبل از recovery ساخته شود، چون orchestration بدون postcondition و reconciliation قابل اعتماد نیست.

---

# Phase G: Recovery & Reconciliation Foundation

## Goal

تبدیل uncertain operation از یک log ساده به یک stateful recovery system.

## Problem

uncertain به معنی failure نیست.

تعریف صحیح:

```
operation started
        ↓
runtime lost before final result
        ↓
outcome unknown
```

ممکن است عملیات:

- موفق شده باشد
- شکست خورده باشد
- نصفه انجام شده باشد

بنابراین replay خودکار ممنوع است.

- commit existence

### Process

بررسی:

- PID
- creation time

### Jobs

## Acceptance Criteria

- uncertain بدون evidence موفق یا fail نشود.
- replay کورکورانه وجود نداشته باشد.
- تاریخچه عملیات حذف نشود.
- acknowledgment دستی evidence داشته باشد.

```

```

---

## Element Locator

مختصات نباید source اصلی باشد.

نمونه:

```json
{
 "window": {
   "process": "devenv.exe",
   "title_pattern": "Visual Studio"
 },
 "element": {
   "automation_id": "Save",

   "control_type": "Button"

```

---

## Safety Rules

- window identity قبل از action verify شود.
- stale element دوباره resolve شود.
- multiple match خطا بدهد.
- destructive action audit شود.
- DPI scaling مدیریت شود.

# Phase I: Tool Catalog Profiles & Discovery

## Goal

کاهش ambiguity بدون شکستن typed MCP contract.

---

## Profiles

```text
minimal
coding
git
testing
desktop
browser
operations
full
```

---

## Rules

- full همیشه backward compatible باقی می‌ماند.
- profile فقط discovery را تغییر می‌دهد.
- نام و contract ابزارهای اصلی تغییر نمی‌کند.

---

## Progressive Discovery

ابتدا ابزارهای عمومی نمایش داده می‌شوند.

ابزارهای تخصصی با نیاز واقعی discover می‌شوند.

---

## Tool Guidance

نمونه:

```text
apply_patch:
Use for transactional multi-file edits.

write_file:
Use only for intentional full replacement.

rename_symbol:
Use semantic rename instead of text replacement.
```

# Phase J: Durable Workflow Orchestration

## Goal

ساخت orchestration محدود، قابل بازیابی و مبتنی بر postcondition.

این پروژه workflow عمومی بدون کنترل نمی‌سازد.

---

## Model

```
WorkflowDefinition
    |
    └── StepDefinition[]
          ├── action
          ├── precondition
          ├── timeout
          ├── retry_policy
          ├── postcondition
          ├── reconciliation
          └── compensation
```

---

## Workflow State

```
created
queued
running
waiting
paused
failed
uncertain
reconciling
completed
cancelled
```

---

## Required Features

### Dry Run

قبل از اجرای side effect مسیر مشخص شود.

### Checkpoint

بعد از هر step وضعیت پایدار ذخیره شود.

### Resume

بعد از restart ادامه از آخرین checkpoint معتبر.

### Idempotency

هر workflow و step شناسه idempotency داشته باشد.

### Retry

فقط برای خطاهای transient.

### Compensation

به جای rollback جعلی برای side effectها.

### Security

- secret redaction
- audit trail
- authorization fail closed

# Non Goals

این پروژه شامل موارد زیر نمی‌شود:

- autonomous unrestricted agent
- universal command router
- blind deployment automation
- automatic replay of unknown side effects
- حذف کامل typed tools

---

# Final Success Criteria

## Recovery

- همه uncertainها قابل inspect باشند.
- عملیات بدون evidence resolve نشوند.

## Desktop

- UI با element identity کار کند، نه فقط coordinate.

## Catalog

- discovery بهتر شود بدون شکستن compatibility.

## Workflow

- بعد از crash قابل resume باشد.
- هر step postcondition داشته باشد.
- unknown state قابل مدیریت باشد.
