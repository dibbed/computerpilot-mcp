# Architecture Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver evidence-based recovery, semantic Windows automation, scoped tool discovery, and resumable workflows as four independently releasable increments.

**Architecture:** Extend the existing append-only recovery journal before building higher-level behavior on it. Add UI Automation and catalog selection as isolated registrars, then build workflow persistence on the same evidence and checkpoint contracts. Existing tool names and the default full catalog remain compatible.

**Tech Stack:** Python 3.10+, MCP Python SDK, Pydantic, SQLite, psutil, `uiautomation` on Windows, pytest, Ruff, mypy.

**Spec:** `docs/roadmap/V0.2.1-V0.2.4-ARCHITECTURE-EXPANSION-PLAN.fa.md`

## Global Constraints

- Never replay an uncertain side effect automatically.
- A conclusive state transition requires persisted evidence; acknowledgment is explicit and audited.
- `full` remains the default tool profile and preserves all existing contracts.
- UI mutations re-resolve the locator and require exactly one matching element.
- Workflow actions come from a fixed allowlist; arbitrary shell text is not a workflow action.
- Persisted records redact secrets and bound user-controlled text.
- Each phase has focused tests, full regression, documentation, and its own commit.

## Review Focus

- A legacy schema-v1 journal with malformed/truncated lines must remain readable and must never duplicate uncertainty markers.
- PID reuse must not count as process evidence unless creation time and executable identity also match.
- Duplicate UI element matches and stale elements must fail closed before an action.
- An unknown or empty tool profile must fail startup with actionable guidance; omitted profile must retain the full catalog.
- A workflow interrupted after a side effect but before checkpoint publication must become uncertain, not rerun that step.
