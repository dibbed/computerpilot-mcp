## 2. Main changes completed before and during v0.2.6

### Durable jobs and workflow correctness

- Kept the public durable-job contract consistently on `job_id` across workflow submission, wait, cancellation, external references, result storage, deduplication, and request-key reconciliation.
- Preserved complete job-row metadata during active-row reconciliation.
- Added bounded long-running progress behavior to `job_wait`.
- `job_wait` now returns already-available output immediately.
- When there is no progress, it emits a bounded heartbeat instead of remaining silent for the full caller timeout.
- Default heartbeat interval is five seconds.
- Incremental stdout/stderr chunks use resumable byte cursors.
- Explicit short timeout semantics remain intact.
- Workflow cancellation during retry backoff wins before another attempt starts.
- Workflow leases remain renewed during retry backoff.
- Orphaned-job cancellation wins the concurrent interrupted-state reconciliation after termination.
- New workflow idempotency identity includes exact workflow inputs while migrated legacy rows remain compatible where exact historical input data never existed.

### Recovery and reconciliation

- Expected HTTP 4xx/5xx responses are observable evidence rather than transport failures.
- Redirect status is observed directly instead of being followed before workflow checks.
- HTTP body hashing is bounded so an oversized response cannot falsely prove a SHA-256 postcondition.
- Git staged paths use NUL-delimited raw output so Unicode paths are compared literally.
- Recovery journal append and compaction are serialized across processes.
- Operator acknowledgement evidence remains stable when appends trigger compaction.
- Workflow/workflow-operation identifiers are included in generic recovery mutation targets.
- Server health degrades when unresolved standalone recovery-journal state exists.
- Audit and project-memory first-open Windows locking races were removed by locking zero-length lock files directly.

### LSP edit safety

- Canonicalized workspace edits by path.
- Merged same-file edit groups safely.
- Preserved same-position insertion order.
- Rejected malformed, reversed, and overlapping edits.
- Hardened UTF-16 position conversion for CRLF, trailing/empty lines, surrogate pairs, and non-LSP line separators.
- Symbol rename requires SHA-256 guards for every edited file.

## 4. Long-running wait issue

A reported symptom was that a long-running test/job appeared to never finish because no response was returned for too long.

The relevant fix is the `job_wait` progress/heartbeat contract:

- existing output returns immediately;
- otherwise state changes wake the wait;
- otherwise the default five-second heartbeat bounds silence;
- stdout/stderr progress is returned incrementally with byte cursors;
- explicit shorter caller timeouts still return as real timeouts.

Regression coverage includes heartbeat-with-no-progress, immediate progress return, explicit short timeout, concurrent state update, future-version rejection, connection reuse, and multi-waiter behavior.

## 7. Git workflow note

## 8. Important operational note for the next thread

If the panel reports a tunnel-client ERROR, distinguish three layers before changing Python code:

1. Python MCP/server failure
2. Supervisor/lifecycle failure
3. Upstream `tunnel-client.exe` control-plane/stdio failure

The panel currently classifies structured runtime lines by severity, so an upstream tunnel-client error can appear in Runtime Errors even when the Python MCP is healthy. Correlate the error timestamp with runtime exit/restart timestamps and upstream tunnel-client version before treating it as an MCP application failure.
